1 Intuition

What machine learning actually is

Machine learning is the study of algorithms and methodologies for constructing generalizable models from data. Three words in that sentence carry all the weight:

  • Model — a compact mathematical object (a line, a tree, a network of weights) that stands in for a real-world phenomenon.
  • From data — you do not write the rule; you supply examples and the algorithm proposes the rule.
  • Generalizable — the rule must work on data you have not seen. A model that only explains its training data is a lookup table wearing a lab coat.
Where this sits

Artificial intelligence is the study of rational agents. Machine learning is the set of techniques that learn a general rule from data. Deep learning is a subset of ML built from many-layer neural networks. Generative AI is deep learning aimed at producing text, images or video from prompts. Data science wraps AI together with data mining, statistics and visualization to extract knowledge. This course lives in the middle ring: ML and DL, with the mathematics that makes both legible.

Three kinds of feedback

ML techniques are usually classified by the feedback signal the algorithm receives while learning. The three canonical cases are shown below; almost every algorithm in this course is an instance of one of them.

The machine learning pipeline

The goal is to construct a model of a real-world phenomenon that performs well on newly collected data — or generates new data that is highly similar. Getting there is a fixed sequence of stages; skipping one is the most common cause of a model that looks brilliant in a notebook and fails in production.

  1. Data acquisition. Data is produced by natural or artificial processes and recorded by measurement or sensors. Sources vary: natural vs synthetic; cross-sectional (tabular) vs sequential (time series); modality: waveform, image, video, audio, graph, text. Risk: sampling bias. Your dataset is a sample, and the sample decides what your model can possibly learn.
  2. Cleaning and annotation. Remove noise, extraneous and sensitive information; domain experts supply labels as ground truth. Risk: leakage (information from the future or from the label sneaking into the features) and label noise.
  3. Encoding. Most methods need numbers. Categorical variables become one-hot or binary codes. Risk: encoding an unordered category as an integer implies a false ordering.
  4. Feature engineering. Construct the information relevant to the task. A single pixel cannot tell you "is this a tree?"; a group of observations can. Risk: features that are unavailable at prediction time.
  5. Model selection and training. Choose candidate models from the data type, modality and task; tune hyperparameters on a validation set or by cross-validation. No free lunch (Wolpert, 1997): no algorithm dominates across all problems, so several must be evaluated.
  6. Evaluation. Apply the frozen model to a held-out test set and compute metrics that match the analytical goal. Risk: choosing the metric after seeing the results.
  7. Interpretation and reporting. Visualize, attribute decisions to features, and communicate with domain experts and a general audience. Risk: a model nobody trusts is a model nobody uses.
The one-sentence version

Machine learning is function approximation under uncertainty, and the pipeline exists to make sure the function you approximate is the one you actually care about.

2 Mathematical foundations

2.1 The learning problem, stated precisely

Let $\mathcal{X}$ be an input space and $\mathcal{Y}$ an output space. A supervised learning problem gives us a training set of $N$ i.i.d. samples drawn from an unknown joint distribution $P(\mathbf{x}, y)$:

$$ \mathcal{D} = \big\{(\mathbf{x}^{(1)}, y^{(1)}), \dots, (\mathbf{x}^{(N)}, y^{(N)})\big\}, \qquad (\mathbf{x}^{(i)}, y^{(i)}) \sim P . $$

A hypothesis is a function $f:\mathcal{X}\to\mathcal{Y}$ drawn from a hypothesis class $\mathcal{H}$ (all lines, all degree-3 polynomials, all trees of depth ≤ 4, …). A loss function $\ell:\mathcal{Y}\times\mathcal{Y}\to\mathbb{R}_{\ge 0}$ scores a prediction against the truth. Two quantities matter:

$$ \underbrace{R(f) = \mathbb{E}_{(\mathbf{x},y)\sim P}\big[\ell(f(\mathbf{x}), y)\big]}_{\text{risk (generalization error)}} \qquad\text{vs.}\qquad \underbrace{\hat{R}_N(f) = \frac{1}{N}\sum_{i=1}^{N}\ell\big(f(\mathbf{x}^{(i)}), y^{(i)}\big)}_{\text{empirical risk (training error)}} $$

We can only compute $\hat{R}_N$, but we care about $R$. The whole discipline — regularization, validation, cross-validation, early stopping — exists because these two numbers can diverge.

Linear algebra concept

A model is a vector of parameters $\boldsymbol\theta \in \mathbb{R}^d$; the training data is a matrix $X\in\mathbb{R}^{N\times m}$ (one row per sample, one column per feature) plus a label vector $\mathbf{y}\in\mathbb{R}^N$. Training is a search over $\mathbb{R}^d$, and evaluating a linear model on all $N$ samples at once is a matrix–vector product $X\mathbf{w}$. This is why vectorized NumPy code is not a stylistic choice but the natural notation.

Probability concept

The i.i.d. assumption — independent and identically distributed — is what licenses every average we take. "Identically distributed" means train and test come from the same $P$; when it fails (distribution shift, a new hospital, next year's market) every guarantee below quietly breaks.

2.2 Why the empirical risk is a reasonable proxy

$\hat{R}_N(f)$ is a sample average of the random variables $Z_i = \ell(f(\mathbf{x}^{(i)}), y^{(i)})$, each with mean $R(f)$. The law of large numbers says the average converges. The finite-sample statement is Hoeffding's inequality, and it is worth deriving because it tells you exactly how fast "training error ≈ test error" becomes true.

Proof — Hoeffding bound on the generalization gap
  1. Assume the loss is bounded: $0 \le \ell \le 1$ (for 0/1 loss this is exact). Then each $Z_i \in [0,1]$. Boundedness is what makes the concentration argument work.
  2. Hoeffding's inequality for bounded independent variables states, for any $\epsilon \gt 0$, $$ \Pr\!\left(\big|\hat{R}_N - R\big| \ge \epsilon\right) \le 2\exp\!\big(-2N\epsilon^2\big). $$
  3. Set the right-hand side equal to a confidence level $\delta$ and solve for $\epsilon$: $$ 2e^{-2N\epsilon^2} = \delta \;\Longrightarrow\; \epsilon = \sqrt{\frac{\ln(2/\delta)}{2N}}. $$
  4. Therefore, with probability at least $1-\delta$, $$ \big|\hat{R}_N - R\big| \le \sqrt{\frac{\ln(2/\delta)}{2N}}. $$ The gap shrinks like $1/\sqrt{N}$: quadrupling the data halves the error bars. It also grows with $\ln(1/\delta)$ — only logarithmically — so demanding more confidence is cheap; demanding more data is not.
  5. ∎ This bound is for a single fixed $f$. If you search over $|\mathcal{H}|$ hypotheses and keep the best, you must union-bound over all of them, replacing $\delta$ by $\delta/|\mathcal{H}|$. That extra $\ln|\mathcal{H}|$ is the mathematical origin of the bias–variance trade-off: bigger hypothesis classes fit the training data better but pay a larger generalization penalty.

2.3 Classification metrics, derived

A classifier's behaviour on a labelled test set is tallied in a confusion matrix. Take the positive class as the one you care about detecting (a disease, a fraud, a defect):

Predicted positivePredicted negativeRow total
Actually positiveTPFN$P = TP + FN$
Actually negativeFPTN$N = FP + TN$
Column total$TP+FP$$FN+TN$$TP+FP+FN+TN$
$$ \text{Accuracy} = \frac{TP+TN}{P+N},\qquad \text{Sensitivity} = \frac{TP}{P},\qquad \text{Specificity} = \frac{TN}{N} $$

Sensitivity (recall, true positive rate) answers "of the sick patients, how many did we catch?" Specificity (true negative rate) answers "of the healthy patients, how many did we leave alone?". They are conditional probabilities: $\text{Sensitivity} = \Pr(\hat{y}=1 \mid y=1)$ and $\text{Specificity} = \Pr(\hat{y}=0\mid y=0)$.

Derivation — accuracy is a prevalence-weighted average of sensitivity and specificity

Let $\pi = \Pr(y=1) = P/(P+N)$ be the prevalence and $1-\pi = N/(P+N)$ its complement.

  1. Write accuracy as a sum of the two correct cells, then divide each term by the total: $$ \text{Acc} = \frac{TP + TN}{P+N} = \frac{TP}{P}\cdot\frac{P}{P+N} + \frac{TN}{N}\cdot\frac{N}{P+N}. $$
  2. Recognise the factors: $TP/P = \text{Sens}$, $TN/N = \text{Spec}$, $P/(P+N)=\pi$, $N/(P+N) = 1-\pi$. Hence $$ \boxed{\;\text{Acc} = \pi\cdot\text{Sens} + (1-\pi)\cdot\text{Spec}\;} $$
  3. ∎ Two consequences follow immediately.
    • Accuracy is a weighted average with weights set by the data, not by you. If $\pi = 0.01$, a model with sensitivity 1.0 and specificity 0.0 scores 0.01·1 + 0.99·0 = 1%.
    • The trivial rule "always predict negative" has Sens $=0$, Spec $=1$, so its accuracy is $1-\pi$. For $\pi = 0.05$ that is 95% — higher than a genuinely good model with Sens $=$ Spec $= 0.9$, whose accuracy is $0.05(0.9) + 0.95(0.9) = 0.9$.
The accuracy paradox

Accuracy is only meaningful when prevalence is balanced or when you report the pair (sensitivity, specificity) alongside it. This is exactly the "100% accurate" muffin-vs-chihuahua classifier that collapses to 50% on a balanced test set.

When you care about the predicted positive cases — "if we flag this patient, how often are we right?" — you need precision, also called positive predictive value (PPV). Unlike sensitivity, it is a probability given the prediction, so it depends on prevalence.

Derivation — precision (PPV) as a function of prevalence
  1. By definition $\text{PPV} = \dfrac{TP}{TP+FP}$.
  2. Scale the whole test set to size 1 and write each cell as a probability using the chain rule $\Pr(A,B) = \Pr(A\mid B)\Pr(B)$: $$ \Pr(\hat{y}=1, y=1) = \text{Sens}\cdot\pi, \qquad \Pr(\hat{y}=1, y=0) = (1-\text{Spec})\cdot(1-\pi). $$
  3. Substitute into the ratio: $$ \boxed{\;\text{PPV} = \frac{\pi\cdot\text{Sens}}{\pi\cdot\text{Sens} + (1-\pi)\,(1-\text{Spec})}\;} $$
  4. ∎ Now the base-rate lesson becomes arithmetic. Take Sens $=0.99$, Spec $=0.99$, and a rare disease with $\pi = 0.001$: $$ \text{PPV} = \frac{0.001(0.99)}{0.001(0.99) + 0.999(0.01)} = \frac{0.00099}{0.01098} \approx 9\%. $$ A 99%-accurate test is wrong ten times out of eleven when it fires on a rare condition. The algebra does not care that the test is good; the base rate dominates.

To collapse a confusion matrix into one number that is robust to prevalence, average the two conditionals instead of weighting them by the data:

$$ \text{Balanced accuracy} = \frac{\text{Sens} + \text{Spec}}{2}, \qquad F_1 = \frac{2\cdot\text{PPV}\cdot\text{Sens}}{\text{PPV}+\text{Sens}} $$

$F_1$ is the harmonic mean of precision and recall: it punishes the case where one is high and the other is low, which an arithmetic mean would hide.

2.4 Regression metrics

For a regression model $y = f(\mathbf{x})$ evaluated on $N$ samples, the standard metric is mean squared error:

$$ \text{MSE} = \frac{1}{N}\sum_{i=1}^{N}\big(y_i - f(\mathbf{x}_i)\big)^2, \qquad \text{RMSE} = \sqrt{\text{MSE}}, \qquad \text{MAE} = \frac{1}{N}\sum_{i=1}^{N}\big|y_i - f(\mathbf{x}_i)\big| $$

Squaring makes the loss differentiable everywhere and penalizes large residuals quadratically; the absolute value is more robust to outliers but non-differentiable at zero. MSE has units of $y^2$, RMSE restores the units of $y$, and MAE estimates the conditional median rather than the conditional mean.

For clustering, the analogous quantity is the sum of squared error (scatter), which module 09 minimizes:

$$ \text{SSE} = \sum_{j=1}^{K}\sum_{\mathbf{x}\in C_j} \big\|\mathbf{x} - \mathbf{c}_j\big\|_2^2 . $$

2.5 Overfitting, complexity, and regularization

Model complexity controls how wiggly the fitted function can be. Too rigid (degree 1 on a sinusoid) and the model underfits: both training and test error are high. Too flexible (degree 9 on 10 noisy points) and the model overfits: training error goes to zero while test error explodes. The classic picture — from Bishop (2006), used in the lecture notes — is the degree-3 versus degree-9 polynomial fit, and the lab below reproduces it with a slider.

Regularization fights overfitting by adding a penalty for complexity to the objective, with a hyperparameter $\lambda$ trading off the two terms:

$$ g(\boldsymbol\theta, f) = \underbrace{\text{MSE}(\boldsymbol\theta)}_{\text{fit the data}} \;+\; \lambda\cdot \underbrace{R(\boldsymbol\theta)}_{\text{stay simple}} $$
NamePenalty $R(\boldsymbol\theta)$Effect
Ridge (Tikhonov)$\sum_i \theta_i^2 = \|\boldsymbol\theta\|_2^2$shrinks all weights smoothly toward zero
Lasso$\sum_i |\theta_i| = \|\boldsymbol\theta\|_1$sets some weights exactly to zero → sparse model, feature selection
Elastic net$\beta\|\boldsymbol\theta\|_2^2 + \|\boldsymbol\theta\|_1$compromise; useful with correlated features
N.B.

Regularization does not always work — Zhang et al. (2017) showed that deep networks can memorize randomly labelled data while still generalizing on real data, so the classical complexity story is incomplete for modern models. Module 05 derives the bias–variance decomposition that explains when and why the penalty helps.

2.6 Validation and cross-validation

We cannot tune hyperparameters on the test set, or the test set stops being a test set. So the data is split three ways:

  • Training set — fit parameters.
  • Validation set — choose hyperparameters and compare models.
  • Test set — touched exactly once, after everything is frozen.

With limited data, a single validation split is wasteful and noisy. $k$-fold cross-validation partitions the training data into $k$ folds, trains on $k-1$ and evaluates on the held-out fold, rotating which fold is held out:

$$ \widehat{\text{Err}}_{\text{CV}} = \frac{1}{k}\sum_{j=1}^{k} \hat{R}_{F_j}\big(f^{(-j)}\big), \qquad f^{(-j)} = \text{model trained without fold } F_j $$

Variants, and when each is required:

ProtocolHow folds are formedUse when
$k$-foldshuffle, split into $k$ equal parts ($k = 5$ or $10$ typical)large, balanced datasets
Leave-one-out (LOOCV)$k=N$; train on $N-1$, test on 1very small datasets
Stratified $k$-foldeach fold preserves class prevalencedefault for classification — otherwise a rare class may be absent from a fold
Stratified group $k$-foldstratify and keep groups (e.g. one patient's many records) in a single foldcorrelated / longitudinal samples

The full hyperparameter-tuning protocol: (1) partition into $k$ folds; (2) for each candidate hyperparameter set $j$, train $k$ times and record mean and standard deviation of the metric; (3) pick $j^{\star}$ with the best mean; (4) retrain on all $k$ folds with $j^{\star}$; (5) evaluate once on the test set. Step 4 matters — the fold models saw only $(k-1)/k$ of the data.

Lab 1 · data splits

Why stratification exists

Drag the prevalence slider down to 5% and switch from stratified to random splitting. A plain random split can hand you a test fold whose positive rate is wildly different from the training fold — your estimate of performance then measures a different problem than the one you trained on. The worst imbalance readout is the largest deviation between a split's positive rate and the true prevalence.

Notice also how small the validation fold gets as you shrink the test fraction: three-way splits are expensive, which is why cross-validation exists.

The dashed curve is the ground truth $\sin(x)$; the dots are 18 noisy training samples. Sweep the degree from 0 to 12 and watch the two error columns. Up to degree 3 the test error falls; past degree 5 the training error keeps falling while the test error climbs — the signature of overfitting, and the reason training loss alone can never be your model-selection criterion.

4 Coding from scratch

The same three implementations, in the same order, every module: pure Python so nothing hides, NumPy so it scales, and scikit-learn so you recognise production code. The repository ships these as the tested module mlfs.foundations. 

"""Module 01 — confusion matrices, metrics, splits and k-fold, no libraries."""
import random


def confusion_matrix(y_true, y_pred, positive=1):
    """Count the four cells of a binary confusion matrix."""
    tp = fp = tn = fn = 0
    for t, p in zip(y_true, y_pred):
        if p == positive:
            tp += t == positive
            fp += t != positive
        else:
            fn += t == positive
            tn += t != positive
    return {"tp": tp, "fp": fp, "tn": tn, "fn": fn}


def metrics(cm):
    """Accuracy, sensitivity, specificity, precision, F1, balanced accuracy."""
    tp, fp, tn, fn = cm["tp"], cm["fp"], cm["tn"], cm["fn"]
    n = tp + fp + tn + fn
    sens = tp / (tp + fn) if tp + fn else float("nan")
    spec = tn / (tn + fp) if tn + fp else float("nan")
    prec = tp / (tp + fp) if tp + fp else float("nan")
    f1 = 2 * prec * sens / (prec + sens) if prec + sens else float("nan")
    return {
        "accuracy": (tp + tn) / n,
        "sensitivity": sens,
        "specificity": spec,
        "precision": prec,
        "f1": f1,
        "balanced_accuracy": (sens + spec) / 2,
        "prevalence": (tp + fn) / n,
    }


def stratified_holdout(y, frac, seed=0):
    """Indices of a hold-out set that preserves each class's prevalence."""
    rng = random.Random(seed)
    by_class = {}
    for i, label in enumerate(y):
        by_class.setdefault(label, []).append(i)
    held = []
    for label, idx in by_class.items():
        rng.shuffle(idx)
        held.extend(idx[: max(1, round(len(idx) * frac))])
    return sorted(held)


def k_fold_indices(n, k=5, seed=0):
    """Return k lists of indices covering range(n) exactly once."""
    idx = list(range(n))
    random.Random(seed).shuffle(idx)
    return [idx[i::k] for i in range(k)]


if __name__ == "__main__":
    # A deliberately useless classifier on an imbalanced problem.
    y_true = [1] * 10 + [0] * 90
    y_pred = [0] * 100                      # always predict negative
    m = metrics(confusion_matrix(y_true, y_pred))
    print(f"accuracy = {m['accuracy']:.2f}  sensitivity = {m['sensitivity']:.2f}")
    # accuracy = 0.90  sensitivity = 0.00   <-- the accuracy paradox

    folds = k_fold_indices(n=10, k=5, seed=1)
    assert sorted(i for f in folds for i in f) == list(range(10))

"""Module 01 — the same operations, vectorised with NumPy."""
import numpy as np


def confusion_matrix(y_true, y_pred):
    """Return [[TN, FP], [FN, TP]] — the scikit-learn convention."""
    y_true = np.asarray(y_true).ravel()
    y_pred = np.asarray(y_pred).ravel()
    tn = int(np.sum((y_true == 0) & (y_pred == 0)))
    fp = int(np.sum((y_true == 0) & (y_pred == 1)))
    fn = int(np.sum((y_true == 1) & (y_pred == 0)))
    tp = int(np.sum((y_true == 1) & (y_pred == 1)))
    return np.array([[tn, fp], [fn, tp]])


def metrics(cm):
    tn, fp, fn, tp = cm.ravel().astype(float)
    sens = tp / (tp + fn) if tp + fn else np.nan
    spec = tn / (tn + fp) if tn + fp else np.nan
    prec = tp / (tp + fp) if tp + fp else np.nan
    return {
        "accuracy": (tp + tn) / cm.sum(),
        "sensitivity": sens,
        "specificity": spec,
        "precision": prec,
        "f1": 2 * prec * sens / (prec + sens) if prec + sens else np.nan,
        "balanced_accuracy": (sens + spec) / 2,
    }


def stratified_split(y, frac=0.2, seed=0):
    """Boolean mask selecting a stratified hold-out."""
    y = np.asarray(y)
    rng = np.random.default_rng(seed)
    mask = np.zeros(len(y), dtype=bool)
    for cls in np.unique(y):
        idx = np.flatnonzero(y == cls)
        rng.shuffle(idx)
        mask[idx[: max(1, int(round(len(idx) * frac)))]] = True
    return mask


def mse(y_true, y_pred):
    return float(np.mean((np.asarray(y_true) - np.asarray(y_pred)) ** 2))


def standardize(X):
    """Column-wise (x - mean) / std, computed on the training data only."""
    X = np.asarray(X, dtype=float)
    mu = X.mean(axis=0)
    sd = X.std(axis=0)
    sd[sd == 0] = 1.0
    return (X - mu) / sd, mu, sd


if __name__ == "__main__":
    y = np.array([1] * 10 + [0] * 90)
    cm = confusion_matrix(y, np.zeros_like(y))
    print(cm)                       # [[90  0] [10  0]]
    print(metrics(cm)["accuracy"])  # 0.9
    X = np.random.default_rng(0).normal(size=(200, 3))
    Xs, mu, sd = standardize(X)
    assert np.allclose(Xs.mean(axis=0), 0, atol=1e-12)
    assert np.allclose(Xs.std(axis=0), 1, atol=1e-12)

"""Module 01 — the production version, with scikit-learn."""
import numpy as np
from sklearn.datasets import load_breast_cancer
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import classification_report, confusion_matrix, roc_auc_score
from sklearn.model_selection import StratifiedKFold, cross_validate, train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

X, y = load_breast_cancer(return_X_y=True)          # 569 samples, 30 features

# stratify=y keeps the class ratio identical in both halves
X_tr, X_te, y_tr, y_te = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=0
)

# The scaler lives INSIDE the pipeline: fitting it on the full dataset
# would leak test-set statistics into training.
pipe = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))

cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)
scores = cross_validate(
    pipe, X_tr, y_tr, cv=cv,
    scoring=["accuracy", "balanced_accuracy", "roc_auc"],
)
for name in ("test_accuracy", "test_balanced_accuracy", "test_roc_auc"):
    print(f"{name:26s} {scores[name].mean():.3f} +/- {scores[name].std():.3f}")

pipe.fit(X_tr, y_tr)                                # refit on all training data
y_hat = pipe.predict(X_te)
y_prob = pipe.predict_proba(X_te)[:, 1]

print("\nconfusion matrix [[TN FP] [FN TP]]:")
print(confusion_matrix(y_te, y_hat))
print(f"\nAUC on the held-out test set: {roc_auc_score(y_te, y_prob):.3f}")
print(classification_report(y_te, y_hat, digits=3))
Reading the three versions side by side: the pure-Python code makes the definitions explicit; the NumPy code shows that metrics are just masked sums; the scikit-learn code shows the two things people get wrong in practice — forgetting stratify=y, and scaling before splitting.
Leakage checklist
  • Fit every transformer (scaler, imputer, encoder, feature selector) on training data only — put them in a Pipeline.
  • Split by group, not by row, when rows are correlated (multiple visits per patient, multiple frames per video).
  • Never use the test set to choose a threshold, a feature subset, or a model.

5 Assessment

Quiz

Q1

An agent is given 10,000 unlabelled chest X-rays and asked to group them by visual similarity. Which paradigm is this?

No labels are supplied, so there is no ground-truth target to approximate — the algorithm must use similarity across features to produce clusters. Semi-supervised learning would require some labels.

Q2

A screening test has sensitivity 0.95 and specificity 0.90. The disease has prevalence 1%. For a patient who tests positive, the probability they actually have the disease is closest to:

$\text{PPV} = \frac{\pi\cdot\text{Sens}}{\pi\cdot\text{Sens} + (1-\pi)(1-\text{Spec})} = \frac{0.01(0.95)}{0.01(0.95)+0.99(0.10)} = \frac{0.0095}{0.1085} \approx 8.8\%$. This is the base-rate fallacy: sensitivity is a property of the test, PPV is a property of the test and the population.

Q3

Training error keeps falling as you increase polynomial degree while validation error rises. The model is:

Falling training error together with rising validation error is overfitting. Reduce capacity (lower degree, shallower tree, fewer neurons) or add an $\ell_1/\ell_2$ penalty.

Q4

Why must feature selection be performed inside each cross-validation fold rather than once on the whole dataset?

Selection uses the labels of every sample, including the ones that later become the held-out fold. That is leakage: the fold is no longer unseen, and the reported error is too low. Wrap the selector in a Pipeline.

Q5

You have 40 patients, each contributing 12 hourly records. Which cross-validation protocol is appropriate?

Records from the same patient are autocorrelated. If some of a patient's hours land in training and others in the test fold, the model can partly memorise the patient and the estimate is inflated. Group the folds by patient, and stratify on the label.

Sensitivity vs. specificity
Definition
Sensitivity $=TP/P$: of the truly positive, the fraction we caught. Specificity $=TN/N$: of the truly negative, the fraction we correctly ignored. Both condition on the truth, so neither depends on prevalence.
Term
Precision (PPV)
Definition
$TP/(TP+FP)$: of the cases we flagged, the fraction that were real. It conditions on the prediction, so it depends heavily on prevalence — rare outcomes make precision collapse even for excellent tests.
Term
Prevalence $\pi$
Definition
The proportion of positives in the population, $P/(P+N)$. It sets the weights in accuracy: $\text{Acc} = \pi\,\text{Sens} + (1-\pi)\,\text{Spec}$.
Term
Hyperparameter
Definition
A choice about the learning algorithm that is not learned from the training data — $k$ in k-NN, $\lambda$ in ridge, tree depth, learning rate. Selected on validation data or by cross-validation.
Term
No free lunch theorem
Definition
Wolpert (1997): averaged over all possible problems, every learning algorithm performs equally. No single model wins everywhere — evaluate several on your data.
Term
Regularization
Definition
Adding $\lambda R(\boldsymbol\theta)$ to the cost to penalise complexity: $g = \text{MSE} + \lambda R$. $\ell_2$ shrinks weights, $\ell_1$ zeroes some out. $\lambda$ trades fit against simplicity.
Term
Data leakage
Definition
Any information about the test set, or about the label, that reaches the model during training. Symptoms: suspiciously good validation scores followed by disappointment in production.
Term
i.i.d. assumption
Definition
Samples are independent and drawn from the same distribution $P$. It is what makes sample averages meaningful, and what breaks under distribution shift.
Term
Stratified $k$-fold
Definition
$k$-fold CV in which each fold preserves the class proportions of the full dataset. The default for classification, because a random fold can miss a rare class entirely.

Practice problems

Easy

Confusion matrix arithmetic

A classifier is evaluated on 500 patients: 60 truly have the condition. It flags 75 patients as positive, of which 45 are true positives. Build the confusion matrix and compute accuracy, sensitivity, specificity, precision and $F_1$.

$TP = 45$, $FP = 75-45 = 30$, $FN = 60-45 = 15$, $TN = 500-60-30 = 410$.

  • Accuracy $= (45+410)/500 = 0.910$
  • Sensitivity $= 45/60 = 0.750$
  • Specificity $= 410/440 = 0.932$
  • Precision $= 45/75 = 0.600$
  • $F_1 = 2(0.6)(0.75)/(0.6+0.75) = 0.667$

Note the gap between accuracy (91%) and precision (60%): most of the accuracy is bought by the 440 negatives. Balanced accuracy $=(0.75+0.932)/2 = 0.841$ is the honest single number here.

Medium

Design the evaluation protocol

You are given 12,000 blood-pressure readings from 800 patients (15 readings each, over a year) and asked to predict whether each reading precedes a cardiac event. Propose a complete protocol: splits, CV scheme, metrics, and three specific leakage risks with mitigations.

Splits. Hold out 20% of patients (160 patients, all 15 readings each) as a test set that is opened once. Use the remaining 640 patients for development.

CV. Stratified group 5-fold on the 640 development patients: groups = patient id, stratification on the event rate. Report mean ± standard deviation across folds.

Metrics. Events are likely rare, so report sensitivity, specificity, precision, balanced accuracy and AUROC — never accuracy alone. If clinicians act on a threshold, also report the confusion matrix at the operating threshold you would deploy.

Leakage risks.

  1. Patient leakage. Readings from one patient in both train and test. Mitigation: group splits, never row splits.
  2. Temporal leakage. Using readings taken after the event, or scaling/imputing with statistics computed over the whole timeline. Mitigation: cut features at prediction time; fit transformers inside each fold.
  3. Duplicate or near-duplicate readings. Identical rows can land in different folds. Mitigation: deduplicate before splitting and verify overlap by patient id.
Hard

Prove the union-bound version of the generalization gap

Suppose $|\mathcal{H}| = M$ hypotheses all have loss in $[0,1]$. Show that with probability at least $1-\delta$, simultaneously for every $f\in\mathcal{H}$,

$$ \big|\hat{R}_N(f) - R(f)\big| \le \sqrt{\frac{\ln(2M/\delta)}{2N}}. $$

Then explain what this implies about adding parameters to a model, and why the bound is loose for deep networks.

  1. For a fixed $f$, Hoeffding gives $\Pr(|\hat R_N(f)-R(f)| \ge \epsilon) \le 2e^{-2N\epsilon^2}$.
  2. Let $E_f$ be that failure event. By the union bound (Boole's inequality), $\Pr\big(\bigcup_f E_f\big) \le \sum_f \Pr(E_f) \le 2M e^{-2N\epsilon^2}$.
  3. Set $2Me^{-2N\epsilon^2} = \delta$ and solve: $\epsilon = \sqrt{\ln(2M/\delta)/(2N)}$.
  4. With probability $\ge 1-\delta$ no hypothesis deviates by more than $\epsilon$ — in particular the one you pick after looking at the data. ∎

Implication. The penalty for searching a larger class is only $\ln M$: doubling the number of candidate models adds $\ln 2 \approx 0.69$ to the numerator. "More parameters" is therefore cheap in this bound — one reason it fails to explain deep learning, where the number of parameters is astronomical yet test error still falls with width and data. Modern theory replaces counting with capacity measures (VC dimension, Rademacher complexity, PAC-Bayes) and still does not fully explain the phenomenon (Zhang et al., 2017).

Project 01

An evaluation harness you would trust with a patient

Every later module will be judged by the harness you build here. The deliverable is a small, reusable Python package (or notebook plus module) that takes a dataset and a model and produces an evaluation report a clinician, an auditor or a reviewer could read without asking you questions.

Brief

  1. Pick a binary classification dataset with meaningful class imbalance: sklearn.datasets.load_breast_cancer, the UCI Heart Disease dataset, or a public readmission dataset.
  2. Implement split(X, y, groups=None, stratify=True), confusion_matrix(y_true, y_pred) and report(cm) from scratch, then assert parity with scikit-learn on the same inputs.
  3. Produce a report containing: dataset description and prevalence; the split protocol with a diagram; 5-fold stratified CV results (mean ± sd) for at least three models; the test-set confusion matrix at a stated threshold; and a paragraph interpreting sensitivity, specificity and precision in the language of the application domain.
  4. Add a leakage audit: every transformer used, and evidence that it was fitted inside the folds.

Deliverables

  • Repository with README.md, evaluate.py, report.ipynb
  • Unit tests proving parity with scikit-learn
  • One-page report (Markdown or PDF) with the required sections
